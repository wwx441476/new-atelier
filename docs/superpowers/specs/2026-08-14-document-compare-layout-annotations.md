# 文档对比：三列布局与页面一键批注

**日期：** 2026-08-14  
**状态：** 已落地（页面渲染批注；不写回原文件、不下载）  
**范围：** `atelier-web` 文档对比页 + 定位锚点匹配修复（`atelier-document`）

---

## 背景

文档对比原先为「上：A/B 预览，下：差异列表」的上下布局，对照效率低。同时预览块虽有稳定 `blockId` / 锚点预留，但：

1. 点击段落/结构差异时常出现「该差异暂无预览锚点」；
2. 希望利用现有对比结果，在预览中一键标出差异（批注），先做页面渲染，不做 Word 写回。

---

## 目标

1. **布局**：对比成功后改为三列 —— 预览 A | 预览 B | 差异。
2. **定位**：修复表格行等场景下 diff 挂不上 `blockIds` 的问题；前端增加文本反查兜底。
3. **一键批注**：用现有 `CompareResult` 在预览中渲染相对视角批注；支持批注目标 A / B / A+B。
4. **非目标（本期）**：写回 docx 原生批注、下载 annotated 文件、持久化评审会话、划词批注。

---

## 一、三列布局

### 思路

对照期望稿：文件信息与工具栏在上，主区三列并排，差异不再压在预览下方，便于左右预览与差异联动。

### 实现要点

| 项 | 说明 |
|----|------|
| 主文件 | `atelier-web/src/pages/DocComparePage.tsx` |
| 列宽 | 宽屏 `xl={8}` 各 1/3；窄屏纵向堆叠 |
| 滚动 | 三列 body 统一 `height: calc(100vh - 280px)`，独立滚动 |
| 工具栏 | 选项 / 开始对比 / 统计标签放在三列上方 |
| 无预览时 | 差异仍整行展示，避免空白 |

## 二、预览锚点「暂无预览锚点」

### 根因

| 层 | 行为 |
|----|------|
| 段落/结构 Diff | 表格行拼接用 `a \| b`（竖线） |
| 预览定位索引 | 表格扁平化为 Tab 拼接 |
| 归一化 | 只去空白，`\|` 残留 → 片段匹配失败 → `blockIds` 为空 |

文字 Diff 基于预览明文重算，行区间映射相对可靠；段落/结构依赖 snippet 匹配，最容易空锚点。

### 方案

1. **后端** `PreviewTextNormalize.normalizeForLocate`：定位时把 `|` / `｜` 当分隔符去掉，与 Tab 对齐。  
   - `PreviewLocateIndex.blockIdsForSnippet` 改用该归一化；增强多行/前缀回退。
2. **前端** `resolvePreviewBlockIds`：`blockIds` 为空时，用旧/新文本在预览 IR 中反查（无需重跑对比即可改善体验）。
3. **点击定位** `DocComparePage.locate`：优先 API 锚点，失败再文本兜底。

### 关键文件

- `atelier-document/.../preview/PreviewTextNormalize.java`
- `atelier-document/.../preview/PreviewLocateIndex.java`
- `atelier-web/src/components/document/resolvePreviewBlockIds.ts`
- `atelier-web/src/components/document/scrollToPreviewBlock.ts`

## 三、一键批注（页面渲染）

### 产品收敛过程

| 阶段 | 方向 | 结论 |
|------|------|------|
| 初议 | 持久评审 / 写回 Word | 任务 TTL、无文档库、POI Comment 成本高 |
| 收窄 | 「利用现有结果一键标差异」 | 先页面渲染，不下载 |
| 挂载侧 | 只 A / 只 B / 双侧 | **默认 B**，可选 A、B、A+B |
| 文案视角 | 双侧相同「旧→新」 | 改为**相对视角**（见下） |
| 用语/样式 | 「改为/改自」、绿字 vs 红划线 | 统一为「修改」+ 对方文案同一橙色样式 |

### 相对视角语义

批注表达的是「本侧相对另一侧发生了什么」，而不是双侧贴同一句旧→新。

| 预览 | 块内批注 | 文首摘要（无正文落点） |
|------|----------|------------------------|
| **A** | `相对B·删除` / `相对B·修改`（对方文案 → 本文） | `相对B·新增`（B 有 A 无） |
| **B** | `相对A·新增` / `相对A·修改`（对方文案 → 本文） | `相对A·删除`（A 有 B 无） |

说明：

- **纯删除**只落在 A 的对应块；B 正文无该块，故用 B 文首摘要列出「相对A·删除」。
- **纯新增**只落在 B 的对应块；A 用文首摘要列出「相对B·新增」。
- **修改**双侧各挂一条，展示统一为：`橙色对方文案 → 本文`（无删除线）。

### 数据流

```
CompareResult
  paragraphOps / structureOps / textHunks
        │
        ▼
buildDiffAnnotations()
  ├─ a / b：按 blockId 挂载
  ├─ aSideNotes / bSideNotes：无落点摘要
  └─ 去重：同文案指纹、同块/跨块嵌套（大范围套小范围）、删/增与修改冲突
        │
        ▼
FlowStructureReader
  annotationsByBlockId + sideNotes
```

### 去重与踩坑（过程要点）

1. **同文案多来源**：段落 + 结构 + 文字 hunk 对同一处各挂一次 → 按内容指纹只留一条；优先级段落 > 结构 > 文字。
2. **一 op 多 blockId**：snippet `contains` 可返回多个 id → 每侧只取 primary 一个块。
3. **大范围套小范围**：如整表行修改 vs「缩短 70%→60%」。  
   - 错误做法：把 old+new 拼成一串再 `includes`（大段中间会插入整段新文，短语匹配失败）。  
   - 正确做法：分别判断 `小.old ∈ 大.old` 且 `小.new ∈ 大.new`，保留更短（更具体）的一条。
4. **删除+修改 / 新增+修改**：两篇差异很大时，算法可能对同一标题既出 REMOVED 又出 MODIFIED。同块冲突时保留「修改」，去掉纯删/纯增。

### UI

- 工具栏：`Segmented`（批注 A | 批注 B | A+B）+「一键批注 / 隐藏批注」。
- 开启后对应预览标题显示「已批注」；切换目标立即生效。

### 关键文件

| 文件 | 职责 |
|------|------|
| `atelier-web/src/components/document/buildDiffAnnotations.ts` | 相对视角构建、去重、侧栏摘要 |
| `atelier-web/src/components/document/FlowStructureReader.tsx` | 块级批注条 + 文首 sideNotes |
| `atelier-web/src/components/document/FlowStructureReader.css` | 批注样式（`flow-anno-*`） |
| `atelier-web/src/pages/DocComparePage.tsx` | 布局、批注开关与目标、传入 A/B 批注 |

## 四、决策摘要

| 问题 | 决策 |
|------|------|
| 批注写回文件？ | 否，仅页面渲染 |
| 默认挂哪侧？ | B；可切换 A / B / A+B |
| 文案方向？ | 双侧均为「对方文案 → 本文」 |
| 标签？ | 统一「相对X·修改 / 删除 / 新增」 |
| 修改样式？ | 对方文案统一橙色，无删除线；删除仍红划线，新增仍绿色 |
| B 如何展示删除？ | 文首「相对A·删除」摘要区（正文无块可挂） |

## 五、后续可选

1. **写回 docx**：在定位可靠后，对目标文件插入 Comment 或可见「【对比批注】」标记并下载。
2. **评审会话持久化**：对比结果 + 批注落库，突破 job TTL。
3. **单元格级定位**：表格内细粒度锚点，减少「整表一块」上的批注堆叠。
4. **两篇完全无关文档**：侧栏删除/新增摘要设上限（已做约 40 条），可再加折叠/分组。

---

## 六、验证建议

1. 同文档微调副本：三列布局、点差异高亮、一键批注后 A/B 文案方向与样式一致。  
2. 含表格行改动：原先「暂无锚点」的段落差异可定位；批注不出现「整行 + 短语」双条。  
3. 切换批注 A / B / A+B：仅目标侧显示块注与对应文首摘要。  
4. 两篇主题不同文档：B 文首有「相对A·删除」列表；A 文首有「相对B·新增」列表。
